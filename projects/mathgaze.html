배경 🌱

학생이 문제를 왜 틀렸는지는 답만 봐서는 알 수 없습니다. 이 프로젝트는 LLM이 짚은 풀이의 핵심 구간과 학생의 실제 시선 데이터를 겹쳐서, 시선이 핵심을 놓쳤는지 혹은 한 곳을 헤맸는지를 찾아 인지적 병목을 진단합니다.

문제 정의 🤔

제가 맡았을 때 앱은 이미 완성돼 있었는데 문제를 한 개도 띄울 수 없었습니다. 원인은 코드가 아니라 검증 데이터가 비어 있는 것이었습니다. 그리고 이 고장은 예외도 로그도 없이 조용했습니다.

접근 🛠

  • 데이터 결함이 필터를 뚫고 들어온 세 가지 경로를 각각 추적해 막았습니다 — 이전 검산 결과 미승계, 그림 설명의 수식 오분류, 본문이 통째로 빈 문항.
  • 출제 편중은 두 번 실패한 뒤 세 번째에 맞췄습니다. 유형 배정을 풀 비율대로 바꿔 편중을 14배 → 1.8배로 낮췄습니다(커버리지 100%).
  • 판정을 독립 모델(deepseek-r1:70b)로 3자 대조해, 제외한 11문항 중 원본 라벨이 틀린 것은 0건임을 확인했습니다.
  • 이번에 실제로 터졌던 검사만 모아 재발 방지 스크립트를 커밋했습니다. 문제가 있으면 종료 코드 1을 냅니다.

설계 결정과 근거 ⚖️

분류 단계를 없애고 reasoning 모델로 피벗했다

4차 마감을 앞두고 분류 로직과 수학 특화 모델이 동시에 무너졌습니다. 함께 불안해하는 대신 무너진 부분과 살릴 부분을 나누고, 분류 단계를 제거해 reasoning 모델이 핵심 구간을 직접 뽑게 바꿨습니다. 한 번에 더 안정적인 추출이 가능했습니다.

정답오류만 물려받고 보기누락은 물려받지 않았다

구 전처리의 보류 판정을 전부 승계하면 마커 분할로 이미 복구된 문항까지 버립니다. 실제로 구 보류 13건 중 12건이 그런 경우였습니다.

think 원문에서 8건을 제외했다

한자 혼입 6건과 보기 의존 검산 3건입니다. 후자가 특히 중요한데, 계산이 맞았는데도 "보기에 없으니 내가 틀렸나 봐"라고 되돌아가는 사고 과정을 진단에 넣으면 우리가 탐지하려는 찍기·보기 의존을 모범 사고로 제시하게 됩니다.

이슈 · 고민 기록 🚩

진행하며 실제로 막혔던 지점과 그때 내린 판단입니다.

에러가 안 나는 고장이 제일 오래 산다

이번에 찾은 문제들의 공통점은 전부 조용했다는 것입니다. 확장이 보낸 시선 좌표의 90%를 버리고 있었는데 좌표는 계속 들어오고 로그도 계속 쌓였습니다. 3자 대조 12건이 전부 실패했는데도 exit 0과 빈 결과 파일 때문에 성공으로 기록됐습니다. 마지막에 문제가 있으면 종료 코드 1을 내는 검사 스크립트를 만들고, 일부러 데이터를 깨뜨려 걸리는 것까지 확인했습니다.

배운 것빈 결과 파일은 '검사했더니 문제 없음'과 구분되지 않는다.

출제 편중을 두 번 실패하고 세 번째에 맞췄다

특정 문항이 다른 문항보다 14배 자주 나왔습니다. 1차로 비율대로 배분하니 편중은 3.2배로 줄었지만 7문항이 아예 안 나왔습니다. 2차로 학년 균형을 포기하니 2.5배가 됐지만 얇은 유형이 과대표집됐습니다. 3차에서 유형 배정을 풀 비율대로 바꾸자 1.8배 · 커버리지 100%가 나왔습니다.

배운 것순서로 균형을 강제하는 한 어느 쪽이든 치우친다. 편향 없는 순서란 결국 균등 셔플과 같다.

재생성이 항상 개선은 아니었다

잘린 추론 결과를 발견하고 --force로 다시 만들었더니 또 잘렸고 이번엔 풀이 단계까지 사라졌습니다. 원래 것보다 나빠져서 되돌렸습니다. temperature=0, seed=0인데도 실행마다 결과가 달랐습니다.

배운 것덮어쓰기 전에 지금 것이 쓸 만한지 먼저 본다.

장시간 작업을 개발 PC에서 돌리다 12건을 날렸다

SSH 터널로 대조 작업을 돌리다 터널이 끊겨 12건이 전부 실패했습니다. 결과를 맨 마지막에 한 번만 저장하는 구조라 통째로 날아갔습니다. 한 건 받을 때마다 저장하고 재실행 시 건너뛰도록 고치고, 작업을 서버로 옮겨 nohup으로 돌렸습니다. 이후 VPN이 두 번 끊겼지만 작업은 끝났습니다.

배운 것장시간 작업은 내 노트북의 연결에 묶어두지 않는다.

전제가 틀렸던 것 두 가지를 인정했다

① "오픈 모델은 <think>를 보여준다"— deepseek-r1은 런타임이 추론을 별도 필드로 빼서 안 잡혔습니다. 오픈 모델이라고 항상 되는 게 아니었습니다. ② "시선 로그가 낱말 단위로 찍히니 낱말 단위 진단이 된다"— 구조는 6월부터 있었지만 그 값이 맞는지는 한 번도 검증된 적이 없었습니다. 보정·필터가 없어 몇 px만 빗나가도 '안 본 낱말'로 집계됩니다.

배운 것구조가 있다고 값이 맞는 건 아니다.

결과 📈

출제 가능 문항을 0 → 109로 열었고, 1,212건 중 깨진 AOI 참조 3건을 0으로 만들었습니다. think 주입 가능 문항은 0 → 100, QwQ 캐시는 113 → 120으로 채웠습니다.

한계 🔍

이 결과가 틀렸을 수 있는 지점입니다.

  • 시선이 낱말에 정확히 떨어지는지는 사람이 앉아서 재봐야 확인됩니다. 이게 안 되면 진단 단위를 줄 단위로 내려야 합니다.
  • fixationThresholdMs: 300 같은 임계값에 근거가 없습니다. 학생 데이터가 쌓여야 정할 수 있습니다.
  • SDK가 보내는 표본 11개 중 앱은 2개만 쓰고 9개를 버립니다. 버린 값(보정 좌표, 품질 필터 재료)에 정확도 문제의 답이 상당 부분 있습니다.
