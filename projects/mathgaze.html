문제

앱은 완성돼 있었는데 문제를 한 개도 띄울 수 없었습니다. 원인은 코드가 아니라 검증 데이터가 비어 있는 것이었습니다. 그리고 이 고장은 예외도 로그도 없이 조용했습니다.

접근

  • 데이터 결함이 필터를 뚫고 들어온 세 가지 경로를 각각 추적해 막았습니다.
  • 출제 편중은 두 번 실패한 뒤 세 번째에 맞췄습니다. 유형 배정을 풀 비율대로 바꿔 편중을 14배 → 1.8배로 낮췄습니다(커버리지 100%).
  • 판정을 독립 모델(deepseek-r1:70b)로 3자 대조해, 제외한 11문항 중 원본 라벨이 틀린 것은 0건임을 확인했습니다.
  • 이번에 실제로 터졌던 검사만 모아 재발 방지 스크립트를 커밋했습니다.

결과

출제 가능 문항을 0 → 109로 열었고, 1,212건 중 깨진 AOI 참조 3건을 0으로 만들었습니다.

이슈 · 고민 기록

프로젝트를 진행하며 실제로 막혔던 지점과 그때 내린 판단입니다.

에러가 안 나는 고장이 제일 오래 산다

이번에 찾은 문제들의 공통점은 전부 조용했다는 것입니다. 확장이 보낸 시선 좌표의 90%를 버리고 있었는데 좌표는 계속 들어오고 로그도 계속 쌓였습니다. 3자 대조 12건이 전부 실패했는데도 exit 0과 빈 결과 파일 때문에 성공으로 기록됐습니다. 그래서 마지막에 문제가 있으면 종료 코드 1을 내는 검사 스크립트를 만들고, 일부러 데이터를 깨뜨려 걸리는 것까지 확인했습니다.

배운 것빈 결과 파일은 '검사했더니 문제 없음'과 구분되지 않는다.

출제 편중을 두 번 실패하고 세 번째에 맞췄다

특정 문항이 다른 문항보다 14배 자주 나왔습니다. 1차로 비율대로 배분하니 편중은 3.2배로 줄었지만 7문항이 아예 안 나왔습니다. 2차로 학년 균형을 포기하니 2.5배가 됐지만 얇은 유형이 과대표집됐습니다. 3차에서 유형 배정을 풀 비율대로 바꾸자 1.8배 · 커버리지 100%가 나왔습니다. 순서로 균형을 강제하는 한 어느 쪽이든 치우친다는 것이 결론이었습니다.

배운 것편향 없는 순서란 결국 균등 셔플과 같다.

재생성이 항상 개선은 아니었다

잘린 추론 결과를 발견하고 --force로 다시 만들었더니 또 잘렸고 이번엔 풀이 단계까지 사라졌습니다. 원래 것보다 나빠져서 되돌렸습니다. temperature=0, seed=0인데도 실행마다 결과가 달랐습니다.

배운 것덮어쓰기 전에 지금 것이 쓸 만한지 먼저 본다.

장시간 작업을 개발 PC에서 돌리다 12건을 날렸다

SSH 터널로 대조 작업을 돌리다 터널이 끊겨 12건이 전부 실패했습니다. 결과를 맨 마지막에 한 번만 저장하는 구조라 통째로 날아갔습니다. 두 가지를 고쳤습니다 — 한 건 받을 때마다 저장하고 재실행 시 건너뛰기, 그리고 작업을 서버로 옮겨 nohup으로 실행. 이후 실제로 VPN이 두 번 끊겼지만 작업은 끝났습니다.

배운 것장시간 작업은 내 노트북의 연결에 묶어두지 않는다.
